# Чек-лист приёмки на устройстве и сквозной приёмки до S900

> Карта проекта — [README](README.md), сборка — [DEVELOPMENT](docs/DEVELOPMENT.md), полный реестр Q01–Q15 — [STATUS](docs/STATUS.md).

Единый список проверок, которые нельзя закрыть локальными тестами. Основание — `REVIEW_2026-09-29.md`
(R01–R23), `FIXES_2026-08-27.md` (§1–§10) и этапы доработок 1–5l (см. `git log`). Локальные тесты
(Robolectric) не проверяют настоящую камеру Touptek, Android Keystore, резервное копирование,
сенсорный ввод и сервер S900 — это проверяется здесь.

Отметка по каждому пункту: **✅ принято / ❌ дефект (номер заметки) / — не проверялось**. К ❌ приложить
шаги, ожидаемый и фактический результат и логи.

## 0. Подготовка

| | |
|---|---|
| Сборка | `./gradlew :app:assembleDebug`, записать хеш коммита (`git log -1 --oneline`) |
| Телефон | Android 12+ (для `data_extraction_rules`); отдельно Android 11 и ниже — только раздел 9 |
| Камера | Touptek E3ISPM, USB3, через **USB-C хаб с PD passthrough** (прямое подключение разряжает телефон; Harper HUB-04P ломает хост-режим) |
| Мишени | лист белой бумаги (FFC), нейтральная серая мишень, круг или квадрат известных размеров, линейка |
| Сервер | тестовый S900 с учёткой, у которой есть право создания источника (`tryAllPermission`); второй сервер или вторая учётка для R03/R12 |
| Планшет | реальный или эмулятор Pixel Tablet (только разделы 6–7, без камеры) |

Логи (снимать на весь сеанс проверки):

```
adb logcat -v time -s ToupcamController KernMemory CameraScreenSession CamLibDevice \
  DatabaseBackup ServerSettingsStore drilling-upload FileStorage CameraController JNI_CAM
```

Аудит снимка хранится в БД (`layer.captureAuditJson`) — JSON со значениями запроса, отправленными в SDK
значениями, HRESULT сеттеров, состоянием SDK около снимка и замером памяти. Это **состояние SDK около
снимка, а не доказанные параметры экспонирования кадра**.

## 1. Подключение USB-камеры (R18, R16, R19, этапы 1–2, 4c)

- [ ] **Холодный запрос доступа.** Приложение запущено, камера подключена без ранее выданного доступа →
  системный диалог. «Разрешить» — превью появляется; «Отклонить» — понятная ошибка и кнопка
  «Переподключить», приложение не падает. Логи: наличие extras ответа и итог `hasPermission`.
- [ ] Подключение камеры при открытом экране съёмки — подключение автоматически.
- [ ] Отключить USB во время превью → «Камера Touptek отключена…»; подключить снова → восстановление
  без выхода с экрана (R16).
- [ ] Отключить USB **во время снимка** → ошибка снимка, нового слоя нет (R09), камера восстанавливается.
- [ ] Свернуть приложение и вернуться (экран съёмки и редактор профилей) → превью продолжается, без
  переподключения камеры.
- [ ] Быстро перейти «Съёмка → Профили → Съёмка» → нет ошибки «Камера занята», один владелец камеры (R19).

## 2. Профили и съёмка (R10, R13, R14, R23, FIXES §3/§6/§7, этапы 4a–4b, 4d, 5f, 5j)

- [ ] **Спуск сразу после переключения DAYLIGHT → UF** и многократные быстрые переключения → у каждого слоя
  правильная лампа; в аудите — профиль этой лампы (R10).
- [ ] **Ожидание кадров после переключения** (R10): перед снимком приложение ждёт 2 кадра превью после
  применения профиля (не дольше 2 с). Переключить лампу и сразу снять мишень несколько раз → в JPEG нет
  кадра со «старой» экспозицией/WB (сравнить с кадром, снятым через 2–3 с). Если различия есть —
  записать, сколько кадров нужно камере.
- [ ] «Новый стол» во время снимка недоступен; кадр не попадает в другой стол.
- [ ] Во время снимка блокированы переключатель освещения, «Новый стол», «Назад» и системный «Назад».
- [ ] Редактор профилей: AE/AWB/FFC → попытка сменить лампу, двигать ползунок, выйти — запрещено до
  окончания процедуры (R13). Запуск без подключённой камеры — понятный отказ.
- [ ] Черновики профилей (R23): правка DAYLIGHT → переключение на UF → правка UF → обратно на DAYLIGHT —
  правки **каждой лампы сохраняются** (смена лампы диалога не вызывает, у каждой лампы свой черновик);
  то же в обратном направлении. Пометка «Не сохранено: …» перечисляет обе лампы.
- [ ] Выход из редактора с несохранёнными правками → «Сохранить всё / Не сохранять / Остаться»; проверить
  все три варианта и системный «Назад». Импорт при несохранённых правках предупреждает об их потере.
- [ ] **Границы параметров (R14).** В редакторе ползунки выдержки/усиления в границах SDK этой камеры; в
  подсказке — источник границ. Профиль со значением вне границ → подсказка «будет отправлено в SDK …».
  Снять кадр → в аудите `applied` = ограниченное значение, `results` — HRESULT каждого сеттера.
- [ ] HUD съёмки: «Профиль: выдержка … мс/с · усиление …% · гамма …% · WB R/G/B», без «Фокус» (FIXES §3).
- [ ] Отметка «снят» на сегменте переключателя (галочка, зелёная рамка) появляется **после записи слоя**,
  для обеих ламп; TalkBack читает «…, кадр снят»; при увеличенном шрифте подпись не обрезается (FIXES §6).
- [ ] Длинная выдержка (> 1 с) снимается без таймаута снимка; HUD показывает секунды.

## 3. Изображение (FIXES §1, R17, R11, R22, этапы 4d-1, 4f–4g, 5g)

- [ ] **Геометрия.** Круг/квадрат на превью и в сохранённом JPEG без искажения (не овал). Превью вписано
  с полями, не растянуто.
- [ ] **Кадрирование превью и снимка.** Сравнить поле зрения превью и JPEG по линейке. В журнале при
  подключении: размеры превью и снимка; при предупреждении «Пропорции превью … и снимка … различаются» —
  зафиксировать оба размера (решение о выборе разрешения превью в `jnicam.cpp` — после этой проверки).
- [ ] Размер JPEG = максимальное разрешение снимка камеры (R17), без масштабирования.
- [ ] **FFC.** Белый лист → «Коррекция освещения (FFC)» → эталон принят, в сообщении медиана/пересвет/
  усиление коррекции. Пересвеченный, тёмный и неравномерный фон → отказ с причиной, **прежний эталон
  сохранён** (R22). Пороги DAYLIGHT/UF предварительные — записать фактические значения из сообщений.
- [ ] Время проверки эталона полного кадра (~20 Мп) — по журналу; приемлемо для оператора.
- [ ] Переснять FFC и выйти без сохранения → профиль использует прежний эталон (R11).
- [ ] Отказ FFC → диалог с полным списком причин; «Снять заново» открывает инструкцию. В альбомной и при
  крупном шрифте текст прокручивается до конца.
- [ ] «Удалить эталон» → подтвердить → сохранить профиль → выйти и открыть снова: эталона нет, снимок без
  коррекции (в журнале снимка нет `ffc`); слои, снятые раньше, открываются как прежде.
- [ ] Белый лист на дневном профиле: отказ «баланс белого (0x80004001)» — записать модель камеры, режим
  и журнал применения для Q02.
- [ ] Импорт профилей с эталоном: прозрачный/нулевой по каналу/неравномерный PNG → отказ, прежние профили
  целы; корректный → принят (R11, R22).
- [ ] Повторяемость: перезапуск приложения → снимок той же мишени с тем же профилем визуально и по
  гистограмме совпадает с прежним.

## 4. Диагностика WB/AE (FIXES §2/§4/§5, этапы 5k–5l)

Только сбор данных для решений Q01–Q03, Q13; исправления — по результатам.

- [ ] При подключении: строка «Состояние SDK после подключения … readHresults={…}» — записать коды и
  значения цели/политики AE, `AUTOEXPOSURE_PERCENT`, `LINEAR`, `CURVE`, `BYTEORDER`, `RGB`, Temp/Tint.
- [ ] AE для DAYLIGHT и UF: строка итога «Автоэкспозиция: … за … мс; вызовы…; события…» — есть ли
  `AUTOEXPO_CONV`/`AUTOEXPO_CONVFAIL` и когда относительно фиксированных 1,8 с; есть ли пересвет.
- [ ] AWB для DAYLIGHT и UF: итог «Автобаланс белого…» — события `WBGAIN`/`TEMPTINT`, усиления WB после.
- [ ] Ползунки WB R/G/B влияют на превью? Сопоставить с кодом `tempTint` (отказ чтения Temp/Tint —
  диагностический признак режима RGB Gain, не доказательство).

## 5. Память (R21, этап 4e)

- [ ] Серия 10–20 снимков подряд с FFC и без; строки `KernMemory` — пики Java/native/PSS и их рост по
  номеру замера (утечки нет — рост не накапливается).
- [ ] Съёмка эталона FFC — строка `KernMemory ffc-reference`.
- [ ] Переподключение камеры → память нативного буфера (по PSS) после закрытия.
- [ ] **Скорость сохранения слоя:** строка `KernMemory save-layer` — отметки фаз `validated` (полная
  проверка JPEG), `sha256`, `end` (миниатюра) в мс; записать для полноразмерного JPEG. Проверка эталона
  FFC — по журналу `FFC …` и фазе `quality` строки `KernMemory ffc-reference`.
- [ ] `javaMax` целевого телефона; OOM нет. Решение о мерах (освобождение буфера, JPEG из RGB24) — по
  этим числам.

## 6. Ориентация и адаптивный интерфейс (FIXES §8, этапы 5h–5i)

- [ ] Поворот на экранах съёмки и редактора: кадр не искажается, **камера не переподключается**, превью
  продолжается; в альбомной — кадр слева, панель справа.
- [ ] Поворот **во время снимка** → кадр не теряется, слой записан.
- [ ] Узкое окно multi-window → одна колонка, кадр виден; широкое → две панели.
- [ ] Все четыре диалога редактора профилей (сохранение, FFC, выход с правками, импорт) — в портрете и в
  альбомной.
- [ ] Экран стола в альбомной/на планшете — изображение слева, слои и глубины справа.
- [ ] Списки и формы на планшете не шире ~640 dp, по центру; сетка столов — 2 колонки на телефоне,
  больше на планшете.
- [ ] Клавиатура в альбомной на форме паспорта и в настройках — поля прокручиваются, ввод виден.
- [ ] В панели 280 dp кнопки «Готово» и «Новый стол» помещаются.

## 7. Паспорт, глубины, черновики (R15, этапы 5a–5c)

- [ ] Номер скважины `0012` сохраняется и показывается с нулями; доходит до S900 строкой (раздел 10).
- [ ] Неверные числа (`1,5` в целом, `1..2`, `12а`) — ошибка у поля, значение видно, не сохраняется.
- [ ] Правка паспорта сохраняется без кнопки; «Назад» с неверным полем → при повторном входе
  «Восстановлен несохранённый ввод» с ошибкой; «Отменить изменения» возвращает записанное.
- [ ] Новое долбление: ввод → «Назад» → снова «Новое долбление» → ввод восстановлен; «Создать» — переход
  в съёмку, черновик исчез.
- [ ] Глубины: ввод до досъёмки UF → после досъёмки у обоих слоёв одинаковые глубины.
- [ ] Кровля ≥ подошвы, отрицательная глубина — ошибка у поля; «Переснять» с несохранёнными глубинами
  дожидается записи.
- [ ] Остановка процесса с открытой формой: ввести неверное значение в форму паспорта (и, отдельно,
  глубины стола) → свернуть приложение (кнопка «Домой») → `adb shell am kill com.siams.kern_prototype` →
  убедиться, что процесса нет: `adb shell pidof com.siams.kern_prototype` ничего не выводит (если PID
  остался — `am kill` останавливает только безопасно останавливаемые процессы; проверка не выполнена,
  повторить) → открыть приложение → черновик восстановлен с ошибкой у поля.

## 8. Архив и БД (R07, R08, R09, R02, этапы 1–2, 5e)

- [ ] **Обновление поверх старой версии** (каждой поддерживаемой: v3–v6) с неотправленной парой и
  паспортом → данные, связи, файлы на месте, отправка работает; в `filesDir/db_backup` — копия.
- [ ] Аварийное завершение сразу после записи (WAL) → следующее обновление видит версию, делает копию.
- [ ] Повреждённый файл БД (подменить `kern.db` мусором) → понятная ошибка, файл не удалён и не изменён,
  пустая БД не создаётся.
- [ ] Пересъёмка с остановкой процесса до/после записи JPEG и до/после записи в БД → прежний кадр не
  потерян до фиксации нового (R08).
- [ ] Нехватка места при съёмке → ошибка, прежний слой цел.
- [ ] Отсутствующий/нулевой/повреждённый JPEG перед отправкой → понятная ошибка без ложного SENT (R02).

## 10. Сквозная отправка до S900 (R01, R02, R03, R05, R12, этап 3)

- [ ] Отправка долбления с несколькими столами → **один FoV на стол**, DAYLIGHT и UF с общим `stackUid`,
  правильные `lampType`; паспорт (включая «0012») в фильтрах фотокниги; глубины; построение Core.
- [ ] Прервать связь **после POST изображения, до PUT метаданных** → повтор → один файл слоя с
  актуальными метаданными (R01).
- [ ] Изменить глубину уже отправленного стола → повторная отправка доставляет новые глубины (R01).
- [ ] **Исследовательский сценарий (до ответа Q11):** очистить глубину уже отправленного стола и повторить
  отправку — ожидаемого результата нет; записать фактическое поведение S900 (значение осталось прежним,
  стало пустым, ошибка) для обсуждения Q11.
- [ ] Отправить на A, переключить на B → полный экспорт на B; удалить проект на A и повторить (R03).
- [ ] Правки во время медленной отправки (паспорт, глубина, пересъёмка) → долбление не становится SENT
  с устаревшими данными (R05).
- [ ] Неверный пароль, 401/403, истёкшая сессия, смена пользователя A → B, HTTPS → HTTP (R12).
  «Проверить соединение» подтверждает только доступность (критерий входа — Q10).
- [ ] Размер реального полноразмерного JPEG: лимиты сервера и прокси, таймауты (Q09).

## 11. Нагрузка

- [ ] 50+ столов: список, сетка, просмотр, отправка — без заметных задержек.
- [ ] Групповое удаление: долгое нажатие → выбрать несколько → удалить → подтвердить; «Выбрать все» на 50+
  столах — диалог показывает количество, предупреждение S900 и короткий список, прокручивается в альбомной.
  Во время отправки → отказ сообщением, выбор сохранён, ничего не удалено.
- [ ] Свободное место на исходе — понятные ошибки, данные целы.

## Не принимается этим чек-листом (открыто)

- **R04** — пересъёмка и удаление не синхронизируют уже отправленное содержимое на S900; **R06** — нет
  полной идемпотентности POST изображения. **SENT пока не доказывает полноту архива на сервере**: до
  решений Q06/Q08 не удалять локальный архив по признаку SENT без независимой проверки сервера.
- **Предупреждения о серверной копии** (пересъёмка, удаление слоя, HUD съёмки) показываются только для
  слоёв с сохранённым серверным id — то есть для отправок, о которых приложение знает. Если ответ на POST
  изображения потерян (R06), копия на S900 может существовать без сохранённого id: тогда предупреждения
  не будет. Отсутствие предупреждения не означает, что на сервере снимка нет.
- Вопросы к S900 — что нужно получить:

  | Вопрос | Что нужно получить |
  |---|---|
  | Q04/Q05 — поля паспорта и «Вынос керна» | Точные ключи, типы и смысл полей; допустим ли строковый «Номер долбления»; как переносить старые значения |
  | Q06 — замена и удаление | Как корректно заменить уже отправленный кадр и удалить его на сервере (закрытие R04) |
  | Q07 — завершение обработки | Когда передавать postupload_processing и как подтвердить построение Core после загрузки всех снимков |
  | Q08 — потерянный ответ POST | Как узнать, создан ли объект, и повторить запрос без дубля (закрытие R06) |
  | Q09 — ограничения загрузки | Максимальный размер JPEG, лимиты прокси, таймауты |
  | Q10 — успешный вход | Как однозначно подтвердить авторизацию и права, а не только доступность сервера |
  | Q11 — глубины | Единицы/масштаб; способ явно очистить ранее записанную глубину |
  | Q12 — схема паспорта | Эндпоинт и формат динамического списка полей |

- Решения заказчика:
  - Q01–Q03, Q13 — окончательное поведение AE/WB (после раздела 4);
  - Q14 — нужно ли резервировать архив и что должно восстанавливаться: БД, JPEG, FFC, настройки;
  - Q15 — куда переходить после «Готово»;
  - пороги качества эталона FFC отдельно для дневного света и УФ — по результатам раздела 3.
